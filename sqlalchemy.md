# SQLAlchemy Best Practices

> **Baseline:** Python **3.15** · SQLAlchemy **2.1.6** · Alembic **1.20.1** · psycopg **3.3.6** · PostgreSQL **17** (this repo's production target, per [postgresql.md](postgresql.md); features that need **18** are tagged "since 18") · FastAPI **0.162.0** · Pydantic **2.14.2** · pyright **1.1.414** (strict) · pytest **9.2**
> **Applies to:** PostgreSQL only. Any service in this repo that reads or writes a database through SQLAlchemy.
> **Last researched:** 2026-10-31, from the SQLAlchemy 2.1 docs, migration guide and changelog, the Alembic docs and changelog, the psycopg docs, the FastAPI docs, and PyPI (see [Sources](#19-sources)). Every ✅ code example in this file was run against SQLAlchemy 2.1.6 on both PostgreSQL 17.11 and 18.6, and checked with `ruff format --check`, `ruff check`, `pyright` (strict) and `pytest`.
> **Re-check when:** SQLAlchemy or Alembic ships a new minor version: sections 0, 3, 9, 13 and 16.
> **Related:** [python-pydantic.md](python-pydantic.md) owns the type system, `Decimal`/UTC rules ([§2.2](python-pydantic.md#22-everyday-rules)), t-strings ([§2.3](python-pydantic.md#23-t-strings)) and `Settings`/`get_settings()` ([§11](python-pydantic.md#11-pydantic-settings)). [postgresql.md](postgresql.md) owns PostgreSQL itself — schema design, indexing, locking, zero-downtime migrations and connection routing through Supabase's pooler ([§11.1](postgresql.md#11-using-postgres-from-application-code)); this file is the deeper, SQLAlchemy-specific reference its [§11.3](postgresql.md#113-sqlalchemy-psycopg-and-asyncpg) points to. This file links to those instead of repeating them.

## How to use this file

This file is a set of instructions for anyone writing SQLAlchemy code in this repo, human or AI agent. Follow the rules unless a decision recorded in the repo (an ADR, `CLAUDE.md`, or a ticket) says otherwise.

| Keyword | Meaning |
| --- | --- |
| **MUST** / **MUST NOT** | Required. Breaking it is a bug or a review blocker. |
| **SHOULD** / **SHOULD NOT** | The default. If you deviate, leave a short comment saying why. |
| **AVOID** | Don't, unless there is a clear, documented reason. |
| **MAY** | Allowed when it helps; not required. |

If a rule here conflicts with the official docs for a newer version, the docs win. Update this file in the same PR.

Notes on the examples:
- They use the users / projects / tasks domain: a `User` owns `Project`s, and each `Project` has `Task`s. Each example's first comment gives its file path, and they build on each other (`Base`, `User`, `Project`, `Task` are defined once and reused).
- `lazy from` lines are Python 3.14+ lazy imports (see [python-pydantic.md §2.4](python-pydantic.md#24-lazy-imports-pep-810)): the standard way to break the import cycle between two modules whose models reference each other.
- Blocks marked `# ❌` show what not to do.

## Key rules

- **MUST** build the engine URL with the `postgresql+psycopg://` scheme ([§1](#1-driver-and-connection-url)).
- **MUST** create exactly one `AsyncEngine` per process, in the app's lifespan, and `await engine.dispose()` on shutdown ([§2](#2-engine-and-pooling)).
- **MUST** use `Mapped[]` and `mapped_column()` for every column, never bare `Column` ([§3](#3-declarative-models)).
- **MUST** set `lazy="raise"` on every `relationship()` ([§4](#4-relationships-and-loading)).
- **MUST** use `back_populates` on every relationship pair, never `backref` ([§4](#4-relationships-and-loading)).
- **MUST** create the async session factory once, with `expire_on_commit=False`, and use exactly one `AsyncSession` per request or task ([§5](#5-sessions-and-transactions)).
- **MUST** query with `select()` plus `session.scalars()` / `session.scalar()` / `session.get()`. **MUST NOT** use the legacy `Session.query()` API ([§6](#6-querying-20-style)).
- **MUST** bind every value passed into SQL, through `text()` named parameters or `tstring()`. **MUST NOT** build SQL with an f-string or `%` ([§8](#8-raw-sql-and-security)).
- **MUST** check ownership in the query's `WHERE` clause, not after loading a row by ID alone ([§8](#8-raw-sql-and-security)).
- **MUST** run the FastAPI session dependency with `scope="function"`, so a failed commit becomes an error response instead of a response that was already sent ([§10](#10-fastapi-integration)).
- **MUST** build the Pydantic response model inside the endpoint, while the session is open. **MUST NOT** return an ORM object from an endpoint or a service function ([§10](#10-fastapi-integration)).
- **MUST** review every autogenerated Alembic migration before committing it, and run `alembic check` in CI ([§13](#13-migrations-alembic)).
- **MUST NOT** run migrations at app startup; run them as a separate deploy step ([§13](#13-migrations-alembic)).
- **MUST** test against a real PostgreSQL container, never SQLite ([§15](#15-testing)).
- **MUST NOT** use the SQLAlchemy mypy plugin; it was removed in 2.1 ([§12](#12-typing-pyright-strict)).

## 1. Driver and connection URL

- **MUST** use `postgresql+psycopg://` as the URL scheme, both for the sync engine (Alembic, scripts) and the async engine (the app). psycopg 3 supports both; one driver covers every use in this stack.
  *Why:* a bare `postgresql://` also resolves to psycopg 3 as of 2.1, but writing the scheme out makes the choice explicit and greppable. `postgresql+asyncpg://` is an allowed alternative, but switching to it needs an ADR: it has different prepared-statement and PgBouncer behavior ([§2](#2-engine-and-pooling)).
- **MUST NOT** use `postgresql+psycopg2://` in new code. It still works ("legacy, fully supported"), but gets no new driver features.
- **MUST** build the URL from `Settings.database_url` ([python-pydantic.md §11](python-pydantic.md#11-pydantic-settings)) with `URL.create()` or `make_url(...).set(...)`, never by string-formatting a password into a URL.

```python
# app/db/engine.py
from sqlalchemy import URL, make_url

from app.settings import Settings


def database_url(settings: Settings) -> URL:
    # Pin the driver regardless of what scheme the env var happens to use.
    return make_url(str(settings.database_url)).set(drivername="postgresql+psycopg")
```

## 2. Engine and pooling

- **MUST** create exactly one `AsyncEngine` per process, built once in the app's lifespan (FastAPI) or at module scope (a script).
- **MUST** call `await engine.dispose()` when the process shuts down. Skipping it raises `RuntimeError: Event loop is closed` warnings from connections garbage-collected after the loop ends.
- **MUST** set `pool_pre_ping=True` and a `pool_recycle` shorter than the database's or any proxy's idle timeout, so a stale connection is replaced instead of raising mid-request.
- **SHOULD** size the pool explicitly (`pool_size`, `max_overflow`) rather than relying on the defaults (5 and 10), based on your DB's `max_connections` and the number of worker processes.
- **MUST** use `NullPool` and `connect_args={"prepare_threshold": None}` when connecting through PgBouncer in **transaction** pooling mode.
  *Why:* a pooled connection is handed to a different client between transactions, so SQLAlchemy's own connection pool adds no value and a session-scoped prepared statement from one client can be reused by another, or break with "prepared statement already exists."
- **MUST NOT** pass `echo=True` in anything that runs in production; it logs full SQL to stdout outside the normal logging config. Configure the `sqlalchemy.engine` logger instead.
- **SHOULD** pass `hide_parameters=True` outside local development, so bound values never reach logs or error messages.
- **MUST** call `engine.dispose(close=False)` in a post-fork hook (e.g. gunicorn's `post_fork`) if the process forks after the engine is created, so child processes don't inherit and fight over the parent's live connections.

```python
# app/db/engine.py
from sqlalchemy.ext.asyncio import AsyncEngine, AsyncSession, async_sessionmaker, create_async_engine

from app.settings import Settings


def create_db_engine(settings: Settings) -> AsyncEngine:
    return create_async_engine(
        database_url(settings),
        pool_size=10,
        max_overflow=5,
        pool_timeout=10,
        pool_recycle=1800,
        pool_pre_ping=True,
        hide_parameters=not settings.debug,
    )


def create_session_factory(engine: AsyncEngine) -> async_sessionmaker[AsyncSession]:
    return async_sessionmaker(engine, expire_on_commit=False)
```

```python
# app/db/engine.py (behind PgBouncer in transaction mode)
from sqlalchemy.ext.asyncio import AsyncEngine, create_async_engine
from sqlalchemy.pool import NullPool


def create_db_engine(settings: Settings) -> AsyncEngine:
    return create_async_engine(
        database_url(settings),
        poolclass=NullPool,  # PgBouncer is the pool.
        connect_args={"prepare_threshold": None},  # No server-side prepared statements.
        hide_parameters=not settings.debug,
    )
```

Wiring the engine into FastAPI's lifespan is in [§10](#10-fastapi-integration).

## 3. Declarative models

- **MUST** use `class Base(DeclarativeBase)`, `Mapped[T]` and `mapped_column()` for every column. **MUST NOT** use the legacy bare `Column(...)` style, and **MUST NOT** call `declarative_base()` — it is superseded by `DeclarativeBase`.
- **MUST** derive nullability from the annotation: `Mapped[T]` is `NOT NULL`, `Mapped[T | None]` is nullable. An explicit `nullable=` on `mapped_column()` always wins if given.
- **MUST** set a `MetaData(naming_convention=...)` on `Base`, so every constraint gets a predictable, explicit name. Without it, Alembic can't reliably generate `drop_constraint()` calls for an unnamed constraint.
- **SHOULD** set `type_annotation_map` on `Base` for `datetime.datetime → DateTime(timezone=True)`. The un-mapped default (`DateTime()`, no timezone) silently accepts naive datetimes.
- **SHOULD** use `Annotated` aliases (`UUIDPk`, `CreatedAt`, `Money`, …) for columns repeated across models, so the type, default and DB type live in one place. A PEP 695 `type` alias works the same way and reads cleaner; either form is fine.
  *Why:* checked against 2.1.6 — a `type` alias whose target type is **not** in `type_annotation_map` and has no inline `mapped_column()` still falls back to its underlying Python type (e.g. `type Money = int` maps as a plain `Integer`), so it won't crash, but it also won't inherit anything useful; a `NewType` in the same situation **does** raise `MappedAnnotationError` at class-definition time. Put every bespoke alias either in `type_annotation_map` or give it an inline `mapped_column()`, and don't rely on either one failing loudly.
- **SHOULD** default primary keys to `uuid.uuid7()` (Python 3.14+), not `uuid.uuid4()`. UUIDv7 is time-ordered, so it doesn't fragment a `btree` primary-key index the way v4 does.
- **MUST** set `server_default=func.now()` (and `onupdate=func.now()` for `updated_at`) rather than a Python-side `default=datetime.now`, so the timestamp is assigned by the database under concurrent writes.
- **SHOULD** set `__mapper_args__ = {"eager_defaults": True}` on `Base`. *Why, checked:* without it, reading a `server_default` or `onupdate` column (`created_at`, `updated_at`) right after `flush()` triggers an implicit refresh query — which under `AsyncSession` raises `MissingGreenlet` because the refresh can't run outside the awaited call. With `eager_defaults=True`, SQLAlchemy fetches those columns via `RETURNING` on the same `INSERT`/`UPDATE`, so reading them right after `flush()` just works.
- **SHOULD** map `enum.Enum` (including `StrEnum`) to `Enum(..., native_enum=False, length=N, values_callable=...)` through `type_annotation_map`, not a Postgres native `ENUM` type.
  *Why:* a native `ENUM` needs an `ALTER TYPE ... ADD VALUE` migration — which can't run inside a transaction — for every new status value. `native_enum=False` stores the value as `VARCHAR`, so adding a case is a one-line model change with no DDL. Pass `values_callable` or the column stores the Python member *names*, not the `.value` strings.
- **MUST** index every foreign-key column explicitly (`index=True` or a named `Index`, on the column that *leads* the index). PostgreSQL does not index foreign keys automatically, unlike the primary key it references.
- **MUST** set `ondelete=` on every `ForeignKey` that should cascade or null out at the database level (`"CASCADE"`, `"SET NULL"`, `"RESTRICT"`), and pair it with `passive_deletes=True` on the corresponding `relationship()` ([§4](#4-relationships-and-loading)).
- **SHOULD NOT** use `MappedAsDataclass` by default. *Why:* in 2.1, `default`/`default_factory` on `mapped_column()` and `relationship()` are no longer plain dataclass defaults — a descriptor handles them — and `default`/`insert_default` became mutually exclusive. It's a reasonable opt-in for a model that wants a typed `__init__`, but it adds constraints (no `frozen`/`slots`, mixins must themselves be `MappedAsDataclass`) that aren't worth taking on by default.
- **MUST** exclude relationships from `__repr__`. Printing an unloaded `lazy="raise"` relationship raises; printing a loaded one can pull in a large object graph.
- **SHOULD** wrap a mutable JSON column in `MutableDict.as_mutable(JSONB)` (or reassign the whole value) so in-place mutation (`obj.data["k"] = v`) is tracked. Plain `JSONB` only detects whole-value reassignment.

```python
# app/db/base.py
import datetime
import enum
import uuid
from decimal import Decimal
from typing import Annotated, Any, ClassVar

from sqlalchemy import DateTime, Enum, MetaData, Numeric, func
from sqlalchemy.orm import DeclarativeBase, mapped_column
from sqlalchemy.types import TypeEngine

NAMING_CONVENTION = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}

type UUIDPk = Annotated[uuid.UUID, mapped_column(primary_key=True, default=uuid.uuid7)]
type CreatedAt = Annotated[datetime.datetime, mapped_column(server_default=func.now())]
type UpdatedAt = Annotated[
    datetime.datetime, mapped_column(server_default=func.now(), onupdate=func.now())
]
type Money = Annotated[Decimal, mapped_column(Numeric(12, 2))]


def _enum_values(enum_cls: type[enum.Enum]) -> list[str]:
    return [str(member.value) for member in enum_cls]


class Base(DeclarativeBase):
    metadata = MetaData(naming_convention=NAMING_CONVENTION)
    type_annotation_map: ClassVar[dict[type, TypeEngine[Any]]] = {
        datetime.datetime: DateTime(timezone=True),
        enum.Enum: Enum(enum.Enum, native_enum=False, length=32, values_callable=_enum_values),
    }
    # Fetch server-generated values (created_at, updated_at) with RETURNING on INSERT and
    # UPDATE, so reading them after a flush never triggers a lazy load.
    __mapper_args__ = {"eager_defaults": True}  # noqa: RUF012  # SQLAlchemy types it as Any.
```

```python
# app/tasks/models.py
from app.db.base import Base, CreatedAt, UpdatedAt, UUIDPk
lazy from app.projects.models import Project
lazy from app.users.models import User

import enum
import uuid

from sqlalchemy import ForeignKey, Index, String
from sqlalchemy.orm import Mapped, mapped_column, relationship


class TaskStatus(enum.StrEnum):
    TODO = "todo"
    IN_PROGRESS = "in_progress"
    DONE = "done"


class Task(Base):
    __tablename__ = "tasks"
    __table_args__ = (
        # Leads with project_id, so it also serves as the index for that foreign key.
        Index("ix_tasks_project_id_created_at_id", "project_id", "created_at", "id"),
    )

    id: Mapped[UUIDPk]
    project_id: Mapped[uuid.UUID] = mapped_column(ForeignKey("projects.id", ondelete="CASCADE"))
    assignee_id: Mapped[uuid.UUID | None] = mapped_column(
        ForeignKey("users.id", ondelete="SET NULL"), index=True
    )
    external_ref: Mapped[str | None] = mapped_column(String(64), unique=True)
    title: Mapped[str] = mapped_column(String(200))
    status: Mapped[TaskStatus] = mapped_column(
        default=TaskStatus.TODO, server_default=TaskStatus.TODO.value
    )
    created_at: Mapped[CreatedAt]
    updated_at: Mapped[UpdatedAt]

    project: Mapped[Project] = relationship(back_populates="tasks", lazy="raise")
    assignee: Mapped[User | None] = relationship(lazy="raise")

    def __repr__(self) -> str:
        return f"Task(id={self.id!r}, title={self.title!r})"
```

- **MUST** pass `persisted=` explicitly on every `Computed(...)` column instead of leaving it unset.
  *Why, checked on both versions:* PostgreSQL added `VIRTUAL` generated columns in version 18; PostgreSQL 17 (this repo's production target) only supports `STORED`. Leaving `persisted` unset makes SQLAlchemy 2.1 pick a default **based on the server it's connected to**: `VIRTUAL` on 18+, `STORED` (with a `SAWarning`) on 17. The same model then produces different DDL in CI (likely 18, if that's what runs in test containers) and production (17) unless the database is identical. Set `persisted=True` for the storage this repo actually needs — `STORED`, materialized on write — on every version:
  ```python
  dbl: Mapped[int] = mapped_column(Computed("est * 2", persisted=True))
  ```

## 4. Relationships and loading

- **MUST** use `back_populates` on both sides of every relationship. **MUST NOT** use `backref`; it is legacy and hides one side of the pair from type checkers.
- **MUST** set `lazy="raise"` (or `lazy="raise_on_sql"`) on every `relationship()`, so an un-eager-loaded access fails loudly in tests instead of silently issuing N+1 queries — or, under `AsyncSession`, raising `MissingGreenlet` far from the code that caused it.
  *Why, checked:* accessing a `lazy="raise"` relationship that wasn't eagerly loaded raises `InvalidRequestError` immediately, with the attribute name in the message, both sync and async.
- **SHOULD** eager-load with `selectinload()` for a collection and `joinedload()` for a many-to-one, chosen per query with `.options(...)`.
- **MUST** use `WriteOnlyMapped[...]` (`lazy="write_only"`) for a collection that can grow without bound (e.g. `Project.tasks` once a project can have thousands). It exposes `.select()`, `.add()`, `.add_all()`, `.remove()`, `.insert()`, `.update()`, `.delete()` instead of loading the whole collection into memory, and it is iterable in neither sync nor async code — only querying it is allowed. **MUST NOT** use `lazy="dynamic"` for new code; it's legacy and doesn't work under asyncio.
- **MUST** pair `passive_deletes=True` with `ondelete="CASCADE"` (or `"SET NULL"`) on children owned through a `WriteOnlyMapped` collection. *Why, checked:* the ORM's `cascade="...delete-orphan"` cascade only walks relationships it has *loaded into memory*; it cannot traverse a write-only collection to find rows to delete. `passive_deletes=True` instead lets `ON DELETE CASCADE` do that at the database level when the parent row is deleted — confirmed end to end: deleting a `Project` and flushing removes its `Task` rows even though they were never loaded into the session.
- **MUST NOT** put `"all"` in `cascade=` for a relationship used from async code. `"all"` implies `refresh-expire`, which issues an implicit (blocking) load. List the cascade options you actually want instead.

```python
# app/projects/models.py
import uuid
lazy from app.tasks.models import Task
lazy from app.users.models import User

from sqlalchemy import ForeignKey, String
from sqlalchemy.orm import Mapped, WriteOnlyMapped, mapped_column, relationship

from app.db.base import Base, CreatedAt, Money, UpdatedAt, UUIDPk


class Project(Base):
    __tablename__ = "projects"

    id: Mapped[UUIDPk]
    owner_id: Mapped[uuid.UUID] = mapped_column(
        ForeignKey("users.id", ondelete="CASCADE"), index=True
    )
    name: Mapped[str] = mapped_column(String(100))
    budget: Mapped[Money | None]
    created_at: Mapped[CreatedAt]
    updated_at: Mapped[UpdatedAt]

    owner: Mapped[User] = relationship(back_populates="projects", lazy="raise")
    tasks: WriteOnlyMapped[Task] = relationship(
        back_populates="project",
        cascade="save-update, merge, delete, delete-orphan",
        passive_deletes=True,
    )
```

Querying and writing through a `WriteOnlyMapped` collection (each statement runs against the whole collection, not an in-memory list):

```python
# app/tasks/extras.py
async def open_tasks(session: AsyncSession, project: Project) -> Sequence[Task]:
    return (
        await session.scalars(project.tasks.select().where(Task.status != TaskStatus.DONE))
    ).all()


def add_task(project: Project, title: str) -> Task:
    task = Task(title=title)
    project.tasks.add(task)  # Queued; session.flush() sends the INSERT.
    return task
```

```python
# ❌
class Project(Base):
    tasks: Mapped[list[Task]] = relationship(back_populates="project", backref="project")
    # backref duplicates the other side; with thousands of tasks this also loads
    # the entire collection into memory on first access.
```

## 5. Sessions and transactions

- **MUST** create the `async_sessionmaker` once, at the same scope as the engine (module-level or app state), never per request.
- **MUST** pass `expire_on_commit=False` to the async session factory. *Why:* without it, every attribute access after a commit issues an implicit refresh query, which fails under `AsyncSession` outside an `await`.
- **MUST** use one `AsyncSession` per request (web) or per task (background job). **MUST NOT** share a session across `asyncio.gather()`, across tasks, or across threads.
- **MUST** scope a transaction to one unit of work with `async with session.begin():` (or the FastAPI dependency in [§10](#10-fastapi-integration)), not a bare `session.commit()` called from deep inside a function.
- **MUST** call `await session.rollback()` after a failed `flush()`/`commit()` before reusing the session; a session left in a failed transaction raises on every further operation.
- **SHOULD** use `await session.begin_nested()` (a `SAVEPOINT`) when a specific sub-operation inside a larger transaction needs to fail and roll back without discarding everything else already done in that transaction.
- Know the 2.1 autoflush behavior: **checked** — `session.execute(text(...))` now triggers an autoflush of pending changes first, the same as an ORM `select()`. Previously autoflush only covered ORM-level queries. Code that relied on raw SQL *not* seeing uncommitted ORM changes needs `session.execute(text(...), ..., execution_options={"autoflush": False})` or `with session.no_autoflush:`.

## 6. Querying (2.0 style)

- **MUST** write queries with `select()` and run them through `session.execute()` / `session.scalars()` / `session.scalar()`, or use `session.get()` for a primary-key lookup. **MUST NOT** use the legacy `session.query(...)` API in new code; it's still supported but not evolving.
- **SHOULD** use `scalar_one()` / `scalar_one_or_none()` when the query is expected to return exactly one row or none, rather than `.first()`, so a query that unexpectedly matches more than one row raises instead of silently picking the first.
- **MUST** check `Select.filter_by()` ambiguity when a query joins more than one entity that shares a column name. *Checked:* `select(Task, Project).join(Project).filter_by(name="a")` raises `AmbiguousColumnError` in 2.1 rather than guessing which entity's `name` you meant. Use an explicit `.where(Project.name == "a")` instead.
- **SHOULD** paginate with keyset pagination (`WHERE (created_at, id) > (:a, :b) ORDER BY created_at, id LIMIT :n`) instead of `OFFSET` for anything beyond the first page — `OFFSET` gets linearly slower the deeper you page, keyset pagination doesn't.
- **SHOULD** use `select(exists().where(...))` for an existence check rather than loading a row and checking for `None`.
- **MAY** use `.with_for_update(skip_locked=True)` to claim one row out of a queue without blocking on rows other workers are already processing.
- **SHOULD** use `load_only(..., raiseload=True)` or `defer(col, raiseload=True)` to leave large or rarely needed columns off a query by default, and `lazy="raise"` the same way it's used for relationships, so an un-deferred access fails instead of issuing a second query.

```python
# app/tasks/service.py
async def get_project_for_user(
```

## 7. Writing data

- **SHOULD** use `session.execute(insert(Model), [dict, dict, ...])` for bulk inserts rather than adding objects one at a time; SQLAlchemy batches it as a single multi-row `INSERT` ("insertmanyvalues").
- **MUST** add `returning(Model.id, sort_by_parameter_order=True)` when a bulk insert's generated IDs need to map back to the input rows in order.
- **SHOULD** use PostgreSQL's `insert(...).on_conflict_do_update(...)` for upserts. **MUST** set any `onupdate=` columns explicitly in `set_={...}` — *checked:* an upsert's `ON CONFLICT DO UPDATE` does not run the column's Python-side `onupdate` callable, so `updated_at` has to be listed by hand or it silently stays at its old value.
- **SHOULD** use `session.execute(update(Model), [{"id": ..., **fields}, ...])` for a bulk update keyed by primary key, when every row needs different values.
- **MUST** pass `synchronize_session` deliberately on a criteria-based `update()`/`delete()` that runs inside a session which also has matching objects loaded (`"fetch"` on PostgreSQL re-selects the affected rows via `RETURNING`; `"evaluate"` checks the criteria against loaded objects in Python; `False` skips synchronization entirely and leaves already-loaded objects stale).
- **MAY** use `Session.merge_all()` / `Session.delete_all()` (new in 2.1) when merging or deleting a batch of objects at once.

## 8. Raw SQL and security

- **MUST** bind every value that comes from outside the code into a SQL statement: `text("... WHERE id = :id")` with a params dict, or `tstring(t"... WHERE id = {value}")` (see [python-pydantic.md §2.3](python-pydantic.md#23-t-strings) for the t-string rule in general). **MUST NOT** build SQL with an f-string, `%`-formatting, or string concatenation.
  *Why, checked:* `tstring()` compiles each interpolated value to a bound parameter (`%(param_1)s::VARCHAR`), the same as `text()` with named params — a value containing `'; DROP TABLE tasks; --` is sent as data, not parsed as SQL.
- **MUST NOT** pass untrusted input to `literal_binds` or any "render inline" debugging helper; those exist for logging/debugging and skip parameterization entirely.
- **MUST** pick a dynamic table or column name from an allowlist (e.g. `Model.__table__.c[name]`), never interpolate a user-supplied identifier into SQL text. `literal_column()` and `quoted_name` control *quoting*, not safety — neither escapes a malicious value.
- **MUST** put an ownership or tenant check in the query's `WHERE` clause (see [§6](#6-querying-20-style)'s `get_project_for_user`), not as a separate check after loading by ID alone — the second pattern is an IDOR waiting to happen when someone later adds a code path that skips the check.

## 9. Async specifics

- **MUST** know what `MissingGreenlet` means: an async DBAPI call attempted outside the greenlet context SQLAlchemy sets up around `await`. With the ORM, this is almost always an implicit lazy load — a relationship or deferred column accessed where nothing is `await`ing (a `__repr__`, a background thread, after the session closed). `lazy="raise"` on relationships ([§4](#4-relationships-and-loading)) and `eager_defaults=True` ([§3](#3-declarative-models)) prevent the two most common causes.
- **MUST NOT** use `async_scoped_session`. The SQLAlchemy docs recommend against the "scoped" pattern for new development; pass the `AsyncSession` explicitly through function arguments or a FastAPI dependency instead.
- **SHOULD** use `AsyncSession.stream_scalars()` with `execution_options(yield_per=N)` for a result set too large to load into a list at once; it opens a server-side cursor instead of buffering the whole result.
- **MUST NOT** share one `AsyncEngine` across more than one event loop (for example, reusing a module-level engine in a new `asyncio.run()` in the same process). Dispose it and create a new one per loop, or use `NullPool`.
- **MAY** mix in `AsyncAttrs` and use `await obj.awaitable_attrs.some_relationship` on a model where an occasional explicit lazy load is genuinely wanted; this repo defaults to `lazy="raise"` instead, so the *mixin* is opt-in per model, not a blanket default.
- **SHOULD** limit `AsyncConnection.run_sync(...)` to DDL and reflection (`Base.metadata.create_all`, Alembic's own migration runner); don't reach for it as a general escape hatch around async code.


## 10. FastAPI integration

- **MUST** create the engine and session factory in the app's `lifespan`, and store the session factory on app/request state. **MUST** `await engine.dispose()` in the lifespan's `finally`.
- **MUST** run the session dependency with `scope="function"` (FastAPI ≥0.121), not the default `scope="request"`.
  *Why, checked empirically:* with the default request scope, code after `yield` (including the commit) runs **after** the response has already been sent to the client. A request that commits a duplicate `external_ref` INSERT returns `200` to the caller, and only then does the commit fail server-side with nothing left to do about it. With `scope="function"`, the same failure commits *before* the response is built, so the client correctly gets a `500`.
- **MUST** build the Pydantic response DTO (`Model.model_validate(orm_obj, from_attributes=True)`, or `ConfigDict(from_attributes=True)` on the schema) inside the endpoint or service function, while the session is still open. **MUST NOT** return an ORM instance from an endpoint or a service function, and **MUST NOT** pass one into a background task — serializing it later, after the session has closed, is exactly the kind of access that raises `MissingGreenlet` ([§9](#9-async-specifics)) or returns expired/stale data.
- **MUST** pass primitive IDs (not ORM objects) into `BackgroundTasks`; a background task opens its own session.

```python
# app/db/deps.py
from collections.abc import AsyncIterator
from typing import Annotated

from fastapi import Depends, Request
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker


async def get_session(request: Request) -> AsyncIterator[AsyncSession]:
    session_factory: async_sessionmaker[AsyncSession] = request.state.session_factory
    # Commits when the endpoint returns, rolls back if it raises.
    async with session_factory.begin() as session:
        yield session


# scope="function": the commit runs before the response is sent, so a failed
# commit becomes a 500 instead of an already-sent 201.
SessionDep = Annotated[AsyncSession, Depends(get_session, scope="function")]
```

## 11. Performance

- **MUST** have a way to catch N+1 queries before they reach production: `lazy="raise"` everywhere ([§4](#4-relationships-and-loading)) is the main defense; SQL logging in development and a per-request query counter in tests are a good backstop.
- **SHOULD** use `.stream_scalars()` / `.execution_options(yield_per=N)` ([§9](#9-async-specifics)) for any read that can return an unbounded number of rows, instead of `.all()`.
- **SHOULD** use bulk statements ([§7](#7-writing-data)) for anything writing more than a handful of rows; SQLAlchemy's insertmanyvalues batches them into a small number of round-trips.
- **MUST** index every column a hot query filters or joins on, in addition to foreign keys ([§3](#3-declarative-models)).
- **SHOULD NOT** reach for `lambda_stmt` by default; the docs call it "generally non-essential" outside hot, repeatedly-executed statements. SQLAlchemy's own statement-compilation cache already avoids recompiling the same shaped query.

## 12. Typing (pyright strict)

- **MUST NOT** install or configure the SQLAlchemy mypy plugin — it was removed in 2.1. `Mapped[]` + `mapped_column()` are plain PEP 484 types and work in pyright strict with no plugin.
- **MUST** uninstall `sqlalchemy-stubs` / `sqlalchemy2-stubs` if a dependency pulled them in; they conflict with SQLAlchemy's own types.
- Know the limits of `Row` typing: `select(a, b, c, ...)` only infers a fully typed `Row[...]` up to **10** columns (**8** for `returning()`); beyond that, extra columns type as `Any`. Checked: a two-column `select()` correctly infers `Row[uuid.UUID, str]` and passes pyright strict with zero errors.
- **MUST** use `@some_prop.inplace.setter` / `@some_prop.inplace.expression` (not the repeated-name `@some_prop.setter` style) when defining a `hybrid_property` with a setter or SQL expression — the repeated-name style isn't typeable by pyright or mypy.
- **SHOULD** annotate `type_annotation_map` and any other dict/list class attribute that pyright strict would otherwise flag as a possibly-mutable class default (`RUF012`) with `ClassVar[...]`. Where SQLAlchemy's own type stubs declare an attribute as `Any` (for example `__mapper_args__`), a `noqa: RUF012` with a one-line reason is more honest than fighting the stub.

## 13. Migrations (Alembic)

- **MUST** scaffold with `alembic init -t pyproject_async` for an async app (sync apps use `-t pyproject`). It keeps Alembic's own config in `pyproject.toml` under `[tool.alembic]` instead of a separate `alembic.ini`, and its `env.py` is pre-wired for an async engine.
- **MUST** set `target_metadata = Base.metadata` (the `Base` from [§3](#3-declarative-models), via the module that imports every model — see `app/models.py`), and pass `compare_server_default=True` to `context.configure()`. `compare_type` is already on by default.
- **MUST** review every autogenerated migration before committing it. Autogenerate **cannot** detect:
  - table or column **renames** (they show up as an unrelated add + drop);
  - an added/removed **`PRIMARY KEY`** or **`EXCLUDE`** constraint on its own;
  - changes to a **`CHECK`** constraint's expression;
  - **sequences**, or enum changes on a backend without native `ENUM` (not an issue here, since [§3](#3-declarative-models) uses `native_enum=False`).
- **MUST** run `alembic check` in CI; it fails the build if the models and the latest migration have drifted, without writing a file.
- **SHOULD** run `alembic current --check-heads` in CI too, so a forgotten `alembic merge heads` after two migrations branch is caught before deploy.
- **SHOULD** add a `ruff` post-write hook (`type = "module"`, `module = "ruff"`) so every generated migration is formatted and linted the same as hand-written code — confirmed: it reformats the file and fixes import order automatically right after `alembic revision --autogenerate` writes it.
- **MUST NOT** edit a migration that has already been applied anywhere outside a local, unshared branch. Write a new migration instead.
- **MUST NOT** run migrations from application startup code. Run `alembic upgrade head` as its own deploy step, before the new app version starts receiving traffic — a slow or failing migration should block a deploy, not run once per replica racing the others.
- **SHOULD** set a short `lock_timeout` for the duration of a migration (`SET LOCAL lock_timeout = '5s'`), so a migration that can't acquire a lock fails fast and visibly instead of queuing behind live traffic indefinitely.
- **MUST** wrap `CREATE INDEX CONCURRENTLY` (and its matching `DROP INDEX CONCURRENTLY`) in `op.get_context().autocommit_block()`. *Checked end to end:* `CONCURRENTLY` cannot run inside a transaction; without the autocommit block Postgres rejects it outright, and with it the index is created (and later dropped) without taking a long-lived lock on the table.
- **SHOULD** avoid bundling a large data backfill into a schema-changing migration; the official Alembic cookbook calls unconditional data migrations "not in fact advisable in the general case." Put sizeable data migrations in their own script, run separately from schema changes.
- **SHOULD** use an expand/contract sequence for a breaking schema change deployed alongside new application code (add the new column nullable → backfill → deploy code that writes both → make it required / drop the old column in a later migration), so old and new app versions can both run against the same schema during a rolling deploy.

```python
        connection=connection,
        target_metadata=target_metadata,
        compare_server_default=True,
    )
    with context.begin_transaction():
        # Fail fast instead of queueing behind live traffic while holding a lock.

        await connection.run_sync(do_run_migrations)
    await engine.dispose()
```

## 15. Testing

- **MUST** test against a real PostgreSQL instance via `testcontainers`, pinned to the same major and minor image version as production (`postgres:17.11`, per [postgresql.md §1](postgresql.md#1-versions-and-upgrades)). **MUST NOT** substitute SQLite: it diverges on transaction and savepoint semantics, and has no `JSONB`, `ON CONFLICT`, or array types.
- **MUST** build the schema for tests by running real Alembic migrations (`alembic upgrade head`), not `Base.metadata.create_all()`, at least once per test session — `create_all()` can't catch drift between the models and the migration history.
- **MUST** roll each test back instead of committing to the shared container: open one connection and an outer transaction per test, bind the `AsyncSession` to it with `join_transaction_mode="create_savepoint"`, and roll the outer transaction back in teardown. Code under test is free to call `commit()`; that only releases a `SAVEPOINT` without touching the outer transaction.
- **MUST** set `asyncio_default_fixture_loop_scope` / `asyncio_default_test_loop_scope` to `"session"` in `pytest-asyncio` config when a fixture (like the engine) is session-scoped — otherwise pytest-asyncio tears the event loop down between tests while a session-scoped async fixture is still bound to it.
- **SHOULD** override the FastAPI session dependency with the test's own transactional session (wrapped in `session.begin_nested()`, so the endpoint's own `commit()` call doesn't end the test's transaction early), rather than hitting a second, uncontrolled database connection.
- **SHOULD** add `pytest-alembic`'s ready-made checks (single head, upgrade runs clean, up/down is consistent, models match the migrated DDL) against a throwaway database, separate from the one the app's own tests use.

## 16. Upgrading to 2.1, and deprecated or removed

Moving from 2.0 to 2.1, check code against these:

- `postgresql://` now resolves to **psycopg 3**, not psycopg2. If the app still depends on psycopg2 behavior, pin the URL to `postgresql+psycopg2://` explicitly and plan to move off it.
- `greenlet` is no longer installed with plain `sqlalchemy`; add the `asyncio` extra ([§0](#0-versions-and-upgrades)).
- Autoflush now runs before **every** execution, including raw `text()` — see the note in [§5](#5-sessions-and-transactions).
- `Select.filter_by()` now raises `AmbiguousColumnError` on a name that matches more than one joined entity, instead of guessing — see [§6](#6-querying-20-style).
- `mapped_column.default` / `relationship.default` / a collection's `default_factory` are no longer plain dataclass defaults under `MappedAsDataclass`; `default` and `insert_default` are mutually exclusive ([§3](#3-declarative-models)).
- `Computed()` with no `persisted=` now resolves per-server: `VIRTUAL` on PostgreSQL 18+, `STORED` (with a warning) on 17 — pass `persisted=True` explicitly for the same DDL on every version ([§3](#3-declarative-models)).
- The mypy plugin is gone ([§12](#12-typing-pyright-strict)).

| Don't use | Use instead |
| --- | --- |
| The SQLAlchemy mypy plugin, `sqlalchemy-stubs`/`sqlalchemy2-stubs` | Nothing — `Mapped[]` typing needs no plugin ([§12](#12-typing-pyright-strict)) |
| `declarative_base()` | `class Base(DeclarativeBase)` |
| Bare `Column(...)` on a declarative model | `Mapped[T] = mapped_column(...)` |
| `backref="..."` | `back_populates="..."` on both sides ([§4](#4-relationships-and-loading)) |
| `lazy="dynamic"` | `WriteOnlyMapped[...]` / `lazy="write_only"` ([§4](#4-relationships-and-loading)) |
| `noload()`, `lazy="noload"` | `raiseload()`, `lazy="raise"` ([§4](#4-relationships-and-loading)) |
| `declarative_mixin` | A plain mixin class; it isn't required for a `Mapped[]`-based mixin |
| `session.query(...)` | `session.execute(select(...))` / `session.scalars(...)` ([§6](#6-querying-20-style)) |
| `bulk_insert_mappings()` / `bulk_update_mappings()` | `session.execute(insert(Model), [...])` / `session.execute(update(Model), [...])` ([§7](#7-writing-data)) |
| `ARRAY.Comparator.any()` / `.all()` | `any_()` / `all_()` |
| `Select.distinct(*cols)` | `Select.ext(distinct_on(*cols))` (PostgreSQL) |
| `@prop.setter` / `@prop.expression` on a `hybrid_property` | `@prop.inplace.setter` / `@prop.inplace.expression` ([§12](#12-typing-pyright-strict)) |
| `postgresql+psycopg2://` in new code | `postgresql+psycopg://` ([§1](#1-driver-and-connection-url)) |

## 17. Anti-patterns

- ❌ Letting a relationship default to lazy-loading (no `lazy="raise"`). **MUST** set it explicitly ([§4](#4-relationships-and-loading)).
- ❌ Returning an ORM object from a FastAPI endpoint or a service function. **MUST** build a DTO while the session is open ([§10](#10-fastapi-integration)).
- ❌ Running the session dependency at the default `scope="request"` when it commits. **MUST** use `scope="function"` ([§10](#10-fastapi-integration)).
- ❌ Testing against SQLite because "it's an ORM, the SQL is the same everywhere." **MUST** test against PostgreSQL ([§15](#15-testing)).
- ❌ Running Alembic migrations from the app's startup event. **MUST** run them as a deploy step ([§13](#13-migrations-alembic)).
- ❌ Trusting autogenerate's output without reading it, especially around renames and constraints it can't detect ([§13](#13-migrations-alembic)).
- ❌ Building SQL with an f-string "just this once." **MUST** bind every value ([§8](#8-raw-sql-and-security)).
- ❌ A native Postgres `ENUM` for a status column that will gain values over time. **SHOULD** use `native_enum=False` instead ([§3](#3-declarative-models)).
- ❌ A foreign key with no index. **MUST** index it ([§3](#3-declarative-models)).

## 18. PR checklist

- [ ] Every `relationship()` sets `lazy="raise"` and uses `back_populates`, not `backref`.
- [ ] Every `ForeignKey` column is indexed and has an explicit `ondelete=`.
- [ ] No endpoint or service function returns an ORM object; every response is built with `model_validate(obj, from_attributes=True)` while the session is open.
- [ ] The FastAPI session dependency uses `scope="function"`.
- [ ] No raw SQL is built with an f-string, `%`-formatting, or concatenation; every value is bound.
- [ ] Every autogenerated migration was read and edited by hand where autogenerate can't be trusted (renames, constraint details), and `alembic check` passes.
- [ ] Migrations run as a deploy step, not from app startup.
- [ ] New or changed queries were checked for N+1s (an un-`lazy="raise"` relationship would have caught it).
- [ ] Tests run against a real PostgreSQL container via `testcontainers`, not SQLite, with the schema built from `alembic upgrade head`.
- [ ] `uv run ruff format --check .`, `uv run ruff check .`, `uv run pyright` and `uv run pytest` all pass.
- [ ] `sqlalchemy` and `alembic` are on their pinned ranges ([§0](#0-versions-and-upgrades)); no mypy plugin or stub packages are installed.
